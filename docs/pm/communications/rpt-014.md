## 关键决策点

1. **ClaimCard 编辑入口 placeholder**：`[✏]` / `[⋯] Hide` 都做成 disabled + toast "需 ft-032"，不实现。dispatch 明确移交 ft-032。
2. **PaperDetailPage 改壳**：lazy import ReadingStation，进站才拉 chunk；speed mode 直走 SpeedReadView 不触发 pdf.js download。
3. **PdfViewer worker 配置**：按 react-pdf v9 + Vite 5 已知模式，`pdfjs.GlobalWorkerOptions.workerSrc` 走 `?url` import；vite.config.ts 的 manualChunks 把 `pdfjs-dist` 切出独立 chunk。
4. **bbox 坐标转换**：PDF points 左下原点 → canvas px 左上 + scale；用 `viewport.convertToViewportPoint()`（pdf.js 自带 helper）避免手算 Y 翻转。
5. **响应式断点**：< 1100px notes 折抽屉走 Sheet（shadcn 既有组件），> 1100px 三栏 PanelGroup。
6. **ChipInput 复用**：TagEditor 直接用 ft-027 ChipInput，不重写。
7. **comment append-only**：UI 层禁用编辑/删除，仅 PATCH `{hidden}`；hidden 折叠灰色显示，不彻底隐藏（用户随时能 unhide）。

## 已知 / 用户实测可能发现的 gap

1. **bbox 坐标转换实测**：figure bbox 高亮在某些 PDF 上若有 1-3px 偏移，是 pdf.js viewport 与 docling 提取 scale 的细微差。用户实测如不影响理解就不调；如影响调 EvidenceItem 的 bbox padding。
2. **PDF 全量下载**：论文 1-10MB 全量下载，首屏需 1-3s。Range request 留 ft-030 优化。
3. **textLayer 文本搜索精度**：claim:section 跳转用 section path 前 60 字 substring 模糊查；如 path 与 PDF 实际标题样式差太大（如 "1. Introduction" vs "1 Introduction"）可能搜不到。可接受。
4. **react-pdf v9 Electron file:// 协议下 worker 加载**：dev 模式 vite serve 已验证；frozen Electron 内是否 OK 需用户实测一次。如 worker 路径出错走 `import.meta.url + ?url` 补一行 fallback。
5. **claim 编辑入口 toast**：用户点 `[✏]` 看到 "需 ft-032" toast 后会问什么时候做 — 已规划 iter-017 紧跟本 ft 实测后启动。
