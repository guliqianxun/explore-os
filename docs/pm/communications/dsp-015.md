# 任务: 记忆/编排双层 H0 — 观点状态机 + 事件日志 + topic 种子

## 上下文

explore-os 的"记忆层 + 编排层"，核心是观点 (viewpoint / claim) 的五态状态机。

完整设计：`docs/design/explore-os-formal-spec.md` (v0.2)
架构图：`docs/design/explore-os-architecture.md`
Feature 文档：`docs/pm/features/ft-041.md`
迭代计划：`docs/pm/iterations/iter-023.md`

## 要求

### 1. Django app `apps/explore/`

新建 app，包含以下文件：

**`models.py`** — 9 张表，所有 `db_table = "explore_*"` 前缀：
- `HermesVPState`: (user, viewpoint_id) PK, state + timestamps
- `HermesVPEvent`: 追加日志，from→to + trigger + payload
- `HermesTopic`: topic_id (slug) + name + aliases
- `HermesTopicEdge`: src→dst + relation (prereq/sub/app/rel)
- `HermesActivity`: snapshot_at + topic + activity + consolidation
- `HermesClaimLink`: src→dst + relation (agree/conflict/refine)
- `HermesThread`: title + body + viewpoint_ids + paper_keys
- `HermesThreadNote`: body + created_at
- `HermesOpenQuestion`: question + topic_id

**`signals.py`** — 3 个 signal handler：
1. `UserPaperStatus.post_save`: status=reading/read_kept → paper 的所有 viewpoints unseen→exposed
2. `HermesClaimLink.post_save`: 新建链接 → 双方 confirmed→linked
3. `HermesClaimLink.post_delete`: 删除链接 → 双方 linked→confirmed（仅当该 v 无其他 link）

每个转移产生一条 `HermesVPEvent` 行。dirty topics 标记。

**`activity.py`** — 两个纯函数：
- `compute_activity(user_id, now)` → `{topic_id: A}`
- `compute_consolidation(user_id)` → `{topic_id: C}`

$A$ 公式: $\sum w(\sigma_v) \cdot e^{-\Delta t / 14}$，除以 max 归一化。不落库——由 crunch 调用后写入 snapshot。

**`crunch.py`** — `run_crunch(user_id)` 编排器：
- 调用 `compute_activity` + `compute_consolidation`
- 写入 `HermesActivity`（当日 snapshot）
- 调 `_detect_prereq_gaps` / `_detect_decay_gaps`
- clear dirty topics

**`views.py` + `urls.py`** — 11 个 DRF endpoint（见 ft-041.md 范围章节）。

**`management/commands/crunch.py`** — 手动触发 crunch。
**`management/commands/seed_topics.py`** — 从 paper.keywords + brief.keywords 种 topic。
