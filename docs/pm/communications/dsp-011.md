## Backend 详设（见 spec）

### Step 1: Paper 模型 + key 生成（apps/papers/models.py）

```python
import secrets
from django.db import models

class Paper(models.Model):
    KEY_ALPHABET = "ABCDEFGHIJKLMNOPQRSTUVWXYZ23456789"  # 32 chars, no 0/1/I/O

    key = models.CharField(max_length=8, unique=True, db_index=True)
    title = models.TextField()
    arxiv_id = models.CharField(max_length=64, null=True, blank=True, unique=True, db_index=True)
    doi = models.CharField(max_length=128, null=True, blank=True, db_index=True)
    created_at = models.DateTimeField(auto_now_add=True)

    @classmethod
    def gen_key(cls) -> str:
        return "".join(secrets.choice(cls.KEY_ALPHABET) for _ in range(8))
```

`save()` 中如 `key` 为空：`gen_key()` 三次重试再让 IntegrityError 冒泡。

### Step 2: user_* 4 张表

完整 schema 见 spec。注意：

- `UserPaperStatus` 是 `OneToOneField(Paper)` — paper 创建时 signal 自动建一条 default new
- `UserComment.hidden` BooleanField，PATCH 仅可改这一项；不提供 PUT/DELETE
- `UserTag` `unique_together`
- `UserBacklink` 双向查询通过 `related_name="backlinks_out/in"`

### Step 3: 数据迁移序列（9 个）

按 spec 顺序，每个独立可 `reverse_code`。第 4/7 步是 data migration（不写
schema），用 `RunPython` + `RunPython.noop` 反向。

**关键**：`backfill_papers` 时 title 取顺序：
1. 该 arxiv_id 第一个 SectionMaterial.path（如果是论文标题样式）
2. fallback 到 `arxiv:<arxiv_id>`

判定"是不是论文标题样式"：path 不匹配
`^(\d+\.|abstract|introduction|references|conclusion|appendix)`，且 length > 0。

### Step 4: 既有 model FK 改造

5 类 material 和 interpret 三表加 `paper = ForeignKey(Paper, on_delete=CASCADE, related_name="<name>")`。
**保留** `paper_arxiv_id` 字段（标 deprecated，下个 ft 删）。

查询入口仍走 `paper_arxiv_id`（兼容现有 views.py），但内部尽快切到
`paper.arxiv_id`。

### Step 5: 11 个 DRF endpoints（见 spec）

URL 路由在 `apps/api/urls.py` 追加。`<id>` 用 `re_path` 抓串后 `resolve_paper(s)`
分流 key vs arxiv_id：

```python
PAPER_KEY_RE = re.compile(r"^[A-Z2-9]{8}$")

def resolve_paper(id_or_key: str) -> Paper:
    if PAPER_KEY_RE.match(id_or_key):
        return get_object_or_404(Paper, key=id_or_key)
    return get_object_or_404(Paper, arxiv_id=id_or_key)
```

### Step 6: 既有 endpoint 兼容

`GET /api/papers/<id>/` 既有 schema 不变，新加字段：

```json
{
  "arxiv_id": "...",
  "paper_key": "ABCD2345",
  "title": "...",
  "status": "new",
  "tags": [],
  "n_comments": 0,
  "n_sections": ..., "n_figures": ..., ...
  "sections": [...], "figures": [...], ...
}
```

`GET /api/papers/`（list）`PaperListItem` DTO 加 `paper_key / title / status /
tags / n_comments`。query 接受 `?status=` `?tag=` `?q=`（q 走 icontains，
title + comments，FTS5 留 ft-030）。
