# 任务: 单机 app packaging 调研（ft-022）

## 背景

v1.0 explore-os 长期形态确定为**单机桌面 app**（Tauri 优先，Electron 兜底），
Django 作为 sidecar，DB 切到 SQLite。本任务做选型 + 可行性调研，**不动业务代码**，只产决策文档。

完整 spec 见 [features/ft-022.md](../features/ft-022.md)。

- ❌ 不要尝试实际打包

## 调研产出要求（packaging.md 的最低章节）

### 1. Tauri 路径
- Sidecar 启 Python 的方式（HTTP localhost vs stdio）
- PyInstaller 打包 Django 的实操要点（已知坑：django apps autoreload、template loader、static files）
- 包体大小预估（Rust 壳 ~10MB + WebView + PyInstaller bundle ~80-150MB）
- 跨平台 Windows / macOS / Linux 流程
- 已知 sidecar 失败模式与缓解

### 2. Electron 兜底
- electron-builder + python sidecar 成熟方案
- 包体差距
- Tauri → Electron 切换成本（前端用标准 Web 技术则迁移低）

### 3. SQLite 切换扫描
**实际扫描当前代码库**，列出：
- 所有 model 中可能不兼容 SQLite 的字段（grep `ArrayField` / `JSONField` PG 操作 / `tsvector` / raw SQL migrations）
- 所有 `update_or_create` / `bulk_create` / `objects.raw(...)` 的使用
- 给出 patch 清单（不写 patch 代码，只列文件 + 行号 + 改动方向）

### 4. 桌面端调度器
- APScheduler in-process（推荐）vs Django-Q（依赖 Redis，桌面端不合适）
- 方案 + 用户「立即抓取」按钮设计

### 5. 风险清单
- 防火墙/杀毒拦截 localhost sidecar
- Python runtime 体积悖论
- 自动更新（Tauri updater vs electron-updater）
- 用户数据目录跨平台路径（`%APPDATA%` / `~/Library/Application Support` / `~/.config`）

### 6. Tauri 失败决策点清单
明确列出「满足任一条件即切 Electron」的可量化判定，例如：
- Tauri 2.x sidecar 在 Windows 实测无法稳定启 Python 进程
- 包体超 X MB
- 跨平台构建需手动维护超过 N 处差异

### 7. 现状违反单机假设的耦合点
扫描代码后列出，例如：
- `delivery/email_sender.py` 假设了远程 SMTP 必填
- `config/settings.py` 是否有 hardcoded `DATABASES` 不能切 SQLite
- 任何 hardcoded `localhost:5432` 之类
