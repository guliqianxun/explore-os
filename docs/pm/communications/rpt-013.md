## 关键决策点

1. **白名单文件路径偏差**：dispatch 列的 `apps/papers/{views,serializers,urls,paths}.py`
   实际不存在。本仓库 paper-related views/urls/serializers 都在 `apps/api/`
   下（ft-028 落地后的现状）。按"intent over literal"原则把 `PaperPdfView` /
   URL / DTO 改动放进 `apps/api/views.py | urls.py`，而 `paths.py` 按字面
   新建在 `apps/papers/`（确实是 paper 域逻辑）。
2. **migration 序号**：dispatch 写 0010，但实际 next 是 0004。沿用真实序号；
   逻辑等价。
3. **ingest 写 pdf_path 的位置**：dispatch 写"`apps/api/ingest.py`"，但该文件
   是 chain orchestrator（不接触 PDF 字节）；真实落盘点在
   `apps/api/ingest_views.py::_save_pdf`。改在那里。
4. **`title` 不被覆盖**：`get_or_create + 条件 update_fields=["pdf_path"]`
   而非 `update_or_create(defaults={..., "title": ...})`，避免 ingest 重复落
   PDF 时把 extract 后的真实 title 改回 `arxiv:<id>`。
5. **evidences nested 已有**：`ClaimSerializer.evidences = ClaimEvidenceSerializer(
   many=True, read_only=True)` 在 ft-022 阶段就已存在，`PaperDetailView` 也已
   `prefetch_related("evidences", "counter_signals")`。本派单不再重复造轮子，
   仅补 2 例契约测试锁定 DTO 形状。
6. **Range request 不做**：spec §风险 4 已明，论文 < 10MB 全量可接受。

## 风险 / 遗留

- **无 Range request**：pdf.js 全量下载 PDF。论文一般 1-10MB，dev 实测可接受。
  ft-030 可加 206 Partial Content。
- **Paper 行重复 update**：每次 ingest 同一 arxiv_id 都会触发 1 次
  `paper.save(update_fields=["pdf_path"])`（如果路径不变也会 save 一次条件已加，
  路径相同就跳过）。无副作用，但要意识到。
- **legacy fallback 顺序**：`papers_dir → pdf_legacy_dir`，与 spec 一致。

## 给 frontend dsp-014 的接口契约样例

`GET /api/papers/<paper_key>/`（detail）实测 JSON 关键字段：

```json
{
  "arxiv_id": "2401.10001",
  "paper_key": "ABCD2345",
  "title": "A paper about X",
  "status": "new",
  "tags": [],
  "n_comments": 0,
  "has_pdf": true,
  "pdf_url": "/api/papers/ABCD2345/pdf/",
  "sections": [...],
  "figures": [...],
  "tables": [...],
  "equations": [...],
  "claims": [
    {
      "claim_id": "2401.10001:claim:1",
      "paper_arxiv_id": "2401.10001",
      "text": "self-rewarding via DPO outperforms baseline",
      "text_en": "self-rewarding via DPO outperforms baseline",
      "claim_type": "finding",
      "source_section_path": "Methods / 3.2 Training",
      "confidence": 0.87,
      "evidences": [
        {"material_id": "2401.10001:sec:Methods/3.2", "relation": "supports"},
        {"material_id": "2401.10001:fig:4",          "relation": "supports"}
      ],
      "counter_signals": []
    }
  ]
}
```

`HEAD /api/papers/<id_or_key>/pdf/` → 200 / 404（无 body）；前端 `useHasPdf`
hook 直接探测即可。`GET` 同 endpoint 返回 `Content-Type: application/pdf`，
全量 body（无 Range）。

`has_pdf=False` 时 `pdf_url` 仍是字符串（例如 `/api/papers/ABCD2345/pdf/`）；
仅当 detail 走 legacy material-only 路径（无 Paper 行）时为 `null`。前端
按 `has_pdf` 切 station/speed 即可，不要直接依赖 `pdf_url` 是否 null。
