# ft-015 学术 PDF 解析升级

## 触发条件
ft-014 实战 9 张图命中 8/9（89%）。剩 ~10% 失败属启发式天花板：
- caption + 实际图错位（多栏 / 跨页 / 嵌入正文中段）
- 表格在 PDF 里只是 text + hairline，find_tables 偶尔漏识

要进一步做就要换专业工具。本 feature 跟踪选型决策，**等失败率经常踩到关心的论文再启动**。

## 候选工具

### A. pdffigures2（推荐）
AllenAI 2016。专门做 figure / table 提取 + caption + bbox + 类型分类。
- 实现：纯启发 + 轻量 ML（不是 DL）；调了多年，covers 多栏 / 跨页 / 复合 figure
- 论文准确率：~96%
- 调用：Java 命令或 docker REST
- 输入 PDF → 输出每个 figure 的 PNG + JSON（caption, type, bbox）

**集成代价**：
- docker 起 service（轻量）；接入成本主要在 caption_extractor + figure_picker 替换
- 现有 deep_interpret / email_renderer 不变，因为我们仍只挑一张架构图 + 一张效果图 + 一张表

**收益**：图准确率 89% → 95%+，省去 caption_extractor 的所有正则启发

### B. Nougat（Meta 2023）
端到端 PDF → Markdown（含数学公式 + figure 占位）。
- 视觉 transformer，输入 page image，输出 markdown
- 模型 1.4 GB；推理 CPU 30–60s/PDF，GPU 3–10s/PDF
- 强项：现代 arxiv PDF 的全文 + 公式 + section 结构
- 弱项：figure 不还原图像，只给位置占位（仍需别的工具抽图）

**集成代价**：高（GPU 部署 + 30-60s 推理时延）；但能替代 pdf_chunker + caption_extractor 双模块

### C. 维持现状（启发式）
当前路径：pymupdf + 自写 caption_extractor + 自写 bbox 推断 + figure_picker。
- 89% 命中是自用够用的水平
- 0 额外依赖
- 错位时降级到不附图，邮件仍可读

## 决策点
**等数据**——观察一段时间日报。如果连续 3 天有>30% 论文图错位，启动 A（pdffigures2）。

## 工作量预估（如启动 A）
- 1 天：docker compose 加 pdffigures2 service + 健康检查
- 1 天：替换 caption_extractor 为 pdffigures2 client；适配 bbox 输出
- 0.5 天：测试 + 实战调通 + 比对准确率
- 总：~2.5 天

## 不在范围
- arXiv LaTeX 源码解析（理论 100% 但 .tar.gz 处理 + LaTeX 解析栈太重）
- 多模态 vision LLM 看整页（ft-012 已被 ft-013 否决，避免回退）
