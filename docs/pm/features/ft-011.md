# ft-011 arXiv PDF 拉取 + 章节拆分

## 目标
为精读档（ft-009 deep）提供全文基础。只对 **Top-N（1–3 篇）** 拉取 PDF 并解析。
PDF 处理贵、易失败，不能全量上。

## 设计
- 触发：只在 ft-008 判定为 `tier=deep` 的 item 上执行
- 源约束：只处理 `source_key == "arxiv"` 或 `dedup_key.startswith("arxiv:")`
  （HF Papers 条目本质也是 arxiv id，可复用）
- URL：`https://arxiv.org/pdf/<arxiv_id>.pdf`
- 下载：httpx 流式，size cap 30MB（超出丢弃并降级）
- 存储：落本地 `media/papers/<arxiv_id>.pdf`（gitignore）
- 解析：`pymupdf4llm`（保留结构化 markdown，优于纯文本）
  - 失败降级到 `pymupdf` 原生文本提取
- 章节拆分：按 markdown heading 粗切 → 归桶到 5 档：
  `intro / method / experiments / conclusion / other`
- 每档截断（控 token）：intro 1000 tokens / method 2000 / experiments 1500 /
  conclusion 800 / other drop

## 数据模型
暂时无 DB，落文件 + 内存结构：
- `media/papers/<id>.pdf` 原件
- `media/papers/<id>.json` 结构化 chunks：
  ```json
  {
    "arxiv_id": "...",
    "sections": [
      {"bucket": "method", "title": "3. Method", "text": "..."},
      ...
    ],
    "fetched_at": "...",
    "parser": "pymupdf4llm"
  }
  ```
- 同一 paper 重复请求命中缓存

## 文件范围
- `sources/pdf_fetcher.py`（新）：下载 + 缓存
- `interpret/pdf_chunker.py`（新）：pymupdf4llm 解析 + 章节归桶
- `pyproject.toml`：加 `pymupdf4llm` 依赖
- `.gitignore`：加 `media/papers/`

## 测试
- `tests_pdf_chunker.py`：用一份 fixture PDF（或 markdown 模拟）验证章节归桶
- PDF 下载走 mock，不打真 arXiv

## 验收
- 对精读档每篇产出 `sections` JSON
- 二次运行命中缓存（无 HTTP）
- 30MB+ 文件安全丢弃、链路不崩
