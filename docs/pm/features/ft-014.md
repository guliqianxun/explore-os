# ft-014 略读升级 + 精读多图多表

## 重新校准两档形态

### 略读卡（每篇）
- 标题 + 作者
- **中文 abstract**（LLM 翻译，中文在前）
- 折叠英文原文（`<details>` 标签）
- **框图**（caption=architecture/framework，bbox 渲染 PNG）
- **效果图**（caption=qualitative/comparison/examples，bbox 渲染 PNG）
- 关键词标签

### 精读卡（Top-N）
= 略读卡全部 +
- 方法摘要
- 关键创新（bullets）
- 局限（bullets）
- 视角解读
- **表**（caption=Table N，bbox 渲染 PNG）

类比："博士生组会汇报版"。

## 设计决策（用户拍板）
- Q1 中英排版：中文在前 + 折叠英文
- Q2 全部 items 都拉 PDF（成本可控；缓存命中后第二天更快）
- Q3 图表索引共用——所有 caption 给 LLM 引用 [Fig. N]，不预先分类
- Q4 表用 caption_extractor 已识别的 Table N + bbox 渲染（复用 ft-013 能力）
- Q5 删 one_liner（信息无用且不准）

## 模块改动

### 工具化
- `interpret/figure_picker.py` 扩展：`pick_qualitative` / `pick_table`
- `subscriptions/memory.py`：`PaperRecord.abstract_zh` 替代 `one_liner`
  （旧字段保留为兼容字段，新代码不写）

### LLM
- `interpret/interpretation.py`：`SkimOut` 加 `abstract_zh` 删 `one_liner`；
  `skim_interpret` prompt 改为"翻译中文 abstract + 抽 keywords"
- `interpret/interpretation.py`：`DeepOut` 加 `qualitative_path/caption` +
  `table_path/caption`

### 渲染
- `delivery/email_renderer.py` 重写两档卡：
  - 略读：title + authors + 中文 abstract + 折叠英文 + 2 图 + keywords
  - 精读：略读全部 + 方法摘要 / 创新 / 局限 / 视角 / 表

### Pipeline
- `run_subscription`：所有 deduped items 都走 PDF + caption + 三类图渲染
- 加 `--no-figures` 调试开关

## 成本
- 略读 LLM：每篇 1 次翻译（短，≈ 0.01 元）
- 精读 LLM：每篇 1 次 deep_interpret（≈ 0.05 元）
- 多模态：**0**
- PDF 下载：每篇 5–30 MB，缓存命中后近零
- 单次 15 篇预估：~0.3 元 + ~150–450 MB 带宽（首跑）

## 验收
- 略读卡有中文 abstract + 折叠英文 + 框图（如有）+ 效果图（如有）+ 标签
- 精读卡叠加方法/创新/局限/视角/表
- 邮件 inline_images 含每篇至多 3 张（arch + qual + table）
- 全量测试通过；实战发件 OK
