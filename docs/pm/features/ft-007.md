# ft-007 Email 渲染投递 + CLI

## 目标
把经解读的条目按分组渲染为邮件并投递，同时提供驱动整个管线的 CLI / HTTP 入口。

## 设计

### 渲染
- `Digest` 中间结构：`title / summary / groups: [{name, items: [...]}]`
- `Renderer` 接口，MVP 两个实现：
  - `HtmlEmailRenderer`：HTML 模板，按分组出 section；每 item 展示标题 / TL;DR / 来源标签 / 链接。
  - `MarkdownRenderer`：调试用。
- 分组顺序固定：papers → code → models（MVP 只有 papers）。

### 投递
- `ChannelAdapter` 接口；MVP `EmailAdapter`：SMTP（Django `send_mail`），SMTP 凭据走 env。
- 投递失败记录 `SubscriptionRun.notes`，不重试 item 本身（避免重复邮件），下一轮正常判去重。

### 入口
- **CLI**：Django management commands
  - `manage.py run_subscription <name> [--dry-run]`
  - `manage.py sync_subscriptions <yaml>`
  - `manage.py fetch_source <key> ...`（调试）
- **HTTP**（Postman 手测即可）：
  - `POST /api/subscriptions/{id}/run` → 同步跑一次
  - `GET /api/subscriptions/{id}/runs` → 最近运行历史
- 调度：cron / Windows 任务计划 在外部调用 CLI。

## 验收
1. `manage.py run_subscription diffusion-daily --dry-run` 打印候选与解读。
2. 去掉 `--dry-run` 发出真实邮件到配置邮箱，HTML 可读。
3. 重复执行不重复推送。
4. 通过 Postman 调 `POST /run` 能触发同一流程。
5. 单次运行总成本 < 2 元（自测抽样）。
