# ft-032 ClaimCard 用户修订层

## 战略上下文

ft-029 Reading Station 上线后，用户在阅读时会自然产生两类诉求：

1. **修订 LLM 抽出的 claim 文本**（措辞不准 / 需补个人理解 / 翻译微调）
2. **隐藏无价值 claim**（LLM 误抽 / 重复 / 与论文主线无关）

按 4/28 锁定的"interpret 层 = LLM 一手判断 / user_* 层 = 人工修订"分层原则，
**不能直接改 `Claim.text`**——会破坏 audit trail，且下次 re-interpret 会冲突。

本 ft 引入**覆盖层（override pattern）**：用户编辑落 user 层，前端展示
override 优先、原始 fallback；删除 override 即"还原 LLM 版本"。

## 决策（PM 拍板 4/28）

| # | 决策 | 备注 |
|---|---|---|
| 1 | **方案 A：覆盖层**（不直改 Claim） | 备选 B 直改、C 走 user_comment 都被否 |
| 2 | 单一 `UserClaimEdit` 表，`claim_id` 唯一主键 | 一个 claim 对应 0 或 1 条 override |
| 3 | **hide 也归此表**（D7）`hidden` 字段，不另起表 | claim 修订动作归一 |
| 4 | hidden=true 默认在 SpeedCardPane 不显示，加 `[显示已隐藏 (N)]` toggle | 用户可见，不丢 |
| 5 | 编辑态在 ClaimCard 内联，不弹 modal | 状态 C 见 ft-029 设计图 |
| 6 | 始终保留原文可见（折叠区 `ⓘ Original`）+ `[↶ revert]` 按钮 | 还原即 DELETE override |
| 7 | 修订后 ClaimCard 收起态显示用户版本，标 `✎ edited` 徽章 | 视觉提示 |
| 8 | DELETE endpoint 即 revert；不保留历史版本 | KISS；要历史等 v2.x |

## 范围

### Backend（小，~0.5 天）

#### 1. 模型

```python
# apps/papers/models.py 加（user_* 系列）
class UserClaimEdit(models.Model):
    claim = models.OneToOneField(
        "interpret.Claim",
        on_delete=models.CASCADE,
        related_name="user_edit",
        primary_key=True,
    )
    text_override = models.TextField(blank=True, default="")  # 空字符串 = 仅 hide 不改文本
    hidden = models.BooleanField(default=False)
    edited_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = "papers_user_claim_edit"
```

迁移：`apps/papers/migrations/0011_user_claim_edit.py`（新表，无数据迁移）。

约束：`text_override` 与 `hidden` 至少一个非默认（即不允许两者都空——那就该 DELETE 整行）。
后端 serializer 校验 + DELETE endpoint 处理还原。

#### 2. Endpoints

```
PATCH  /api/claims/<claim_id>/edit/      # body: {"text_override": str, "hidden": bool}
DELETE /api/claims/<claim_id>/edit/      # 还原（删 override 行）
```

PATCH 走 `update_or_create`（SQLite 友好，避 PG `ON CONFLICT`）。

#### 3. DTO 注入

`PaperDetailSerializer.claims[]` 加：

```json
{
  "claim_id": "...",
  "text": "...",                       // 原 LLM
  "text_effective": "...",             // override 优先，否则 = text
  "user_edit": {                       // null 若无 override
    "text_override": "...",
    "hidden": false,
    "edited_at": "2026-04-28T..."
  },
  ...
}
```

frontend 读 `text_effective` 显示主文，`user_edit` 决定徽章 / hidden 状态 / `ⓘ Original` 折叠区。

#### 4. 测试

`tests_user_claim_edit.py` 新建，约 8 例：
- POST → 200 + 入库
- PATCH → 200 + 更新
- DELETE → 204 + 行消失
- hidden=true 不影响 text_override
- 双空校验拒绝
- 跨 paper 不串
- detail DTO `text_effective` / `user_edit` 正确
- Claim 删除级联

### Frontend（中，~2 天）

#### 1. ClaimCard 状态 C：编辑态

ft-029 已在 ClaimCard 留了 `[✏]` 入口 placeholder。本 ft 接通：

```tsx
function ClaimCard({ claim }: { claim: ClaimDTO }) {
  const [mode, setMode] = useState<"collapsed"|"expanded"|"editing">("collapsed");
  const text = claim.text_effective;
  const isEdited = !!claim.user_edit?.text_override;

  if (mode === "editing") {
    return <ClaimEditForm claim={claim} onCancel={() => setMode("collapsed")} />;
  }
  // collapsed / expanded 复用 ft-029 已写
}
```

`ClaimEditForm`：
- textarea 多行（默认填 `text_effective`）
- 折叠 `ⓘ Original (LLM)` 显示原始 `claim.text`，旁边 `[↶ revert]`（disabled if !isEdited）
- 底部 `[Cancel] [Save override]`
- Cmd+Enter / Ctrl+Enter 提交

#### 2. Hide 流程

`[⋯]` 菜单 → `Hide claim` → PATCH `{hidden: true}` → 乐观更新（淡出）。

SpeedCardPane 顶部加 `[显示已隐藏 (N)]` toggle（仅在 N > 0 时出现）。

#### 3. Edited 徽章

ClaimCard 收起态末尾若 `isEdited`，显示 `✎ edited` 小 chip（灰色）。

#### 4. API client

`frontend/src/api/claims.ts`：

```ts
export async function patchClaimEdit(claim_id: string, payload: {text_override?: string; hidden?: boolean}) { ... }
export async function deleteClaimEdit(claim_id: string) { ... }
```

加进 TanStack Query mutation，invalidate `["paper-detail", paper_key]`。

## 验收

1. 编辑 claim → save → 收起态显示新文本 + `✎ edited` 徽章
2. `ⓘ Original` 折叠区正确显示 LLM 原文
3. `[↶ revert]` → DELETE → 收起态回到 LLM 原文，徽章消失
4. hide claim → 从默认列表消失，顶部 `[显示已隐藏 (1)]` 出现
5. 显示已隐藏后 → claim 灰色显示 + `[Unhide]` 按钮
6. 跨 reload 持久（DB 持久，无 localStorage）
7. 同一 claim 多次编辑只留最新 override（OneToOne，update_or_create）
8. backend 8 例测试通过；frontend tsc strict 0 error
9. bundle 增量 < 10KB（仅 form + mutation 代码）

## 风险

1. **OneToOne primary_key 与 Django delete 级联**：Claim 删除时 user_edit 自动清，`on_delete=CASCADE` 保证；但 re-interpret 流程若**重建** Claim（旧 claim_id 不再存在），override 会丢——这是预期行为（claim 变了，旧 override 不该跟着）。
2. **乐观更新 race**：用户快速 edit + revert，需要 mutation queue（TanStack Query 自带）。
3. **text_override 长度无上限**：不加 max_length（claim 可能比 LLM 原文还长，用户补充）。
4. **hidden claim 在 evidence 链中的处理**：claim hidden 不影响其作为其它 claim 的 evidence——本 ft 不做联动隐藏。

## Out of Scope

- ❌ 编辑历史 / 版本回溯（仅最新 override，删即还原）
- ❌ claim 跨用户共享（单机自用，无多用户）
- ❌ claim 级 backlink / 双链（仍 lock paper 级，见 ft-029 OOS）
- ❌ claim 标签 / 评分（如有需要再开 ft）
- ❌ 一键"接受 LLM" 批量操作（无意义，default 即接受）
