# ft-031 桌面通知 + brief 未决分组

## 触发

ft-036 首位用户实测后留下两块"低悬果"：

1. **订阅跑完没反馈**：`run_subscription` 在后台 ~70s 跑完，14 篇 paper 落库；
   但若用户关闭了 SubscriptionPage 切到 PaperListPage 看别的，run 完成时**没
   任何提示**。要么定时刷新，要么不知道何时该回看 brief feed。
2. **未决 paper 分桶感知缺失**：brief feed 速读区当前是 `status=new` 的扁平
   列表（按 created_at 排序）。**新跑的 12 篇** 与 **上次没读完的 8 篇** 混在
   一起，看不到"哪些是这次刚来的"。积压感知差。

两块都不大，合做一刀。

## 决策（2026-04-30 lock）

1. **桌面通知走 Electron Notification API**（不引第三方），main 进程持有，
   preload 暴露 `window.explore.notify(opts)` 给前端。
2. **未决分组按 `Paper.created_at` 分今日 / 一周 / 更早 三段** —— 不引新字段，
   不改 schema。speed cards 区上方挂三个 sticky sub-header 即可。
3. **NavBar Papers 旁挂未决数 badge** —— count = `status=new` papers，
   `react-query` 缓存 60s，refetch on `subscriptions/*/run` job succeed。
4. **桌面通知 dev / browser 模式回退**：浏览器跑（开发用 `npm run dev`）走
   `window.Notification` API；electron 走 IPC → main `new Notification()`。
5. **通知点击行为**：聚焦 Electron 窗口 + `window.location.hash =
   "#/papers?status=new"` —— 跳到 brief feed 未决区。

## 范围

### A. Electron 桌面通知

**electron/src/main.ts**：
- 新增 IPC `explore:notify`：`(title, body, jobId) => void`
- 实现：`new Notification({ title, body, silent: false })`，`on("click")` →
  `mainWindow.show()` + `mainWindow.focus()` + `webContents.send("explore:notification-clicked", jobId)`

**electron/src/preload.ts + types.ts**：
- 暴露 `window.explore.notify(opts: { title, body, jobId? })`
- 暴露 `window.explore.onNotificationClick(handler: (jobId) => void)` （ipcRenderer.on 包装）

**frontend/src/lib/notify.ts**（新文件）：
- `notify(opts)` 优先用 `window.explore?.notify`，回退 `new Notification()`（带权限检查 + 用户首次触发）
- `onNotificationClick(handler)` 同前回退（浏览器模式 `notification.onclick`）

**frontend/src/hooks/useJobPolling.ts**：
- 在 job 状态由非 terminal → `succeeded` 转换时，若 `name.startsWith("run-sub:")` →
  从 detail（已 cached）取 paper 数 / 订阅名 → `notify({ title: "Subscription complete", body: "<sub_name>: <N> new papers", jobId })`
- 需要 job 详情含 N papers —— 走 `useQueryClient().invalidateQueries(["papers"])` 后从 cache 取 list 长度，简化版可只显示订阅名。

### B. 未决分组（brief feed）

**frontend/src/pages/PaperListPage.tsx**：
- `briefGroups` 改：在 `skim`（status=new）内再分桶
  - `skimToday` = `created_at >= 今天 0:00`
  - `skimWeek` = `今天 - 7d <= created_at < 今天 0:00`
  - `skimOlder` = `created_at < 今天 - 7d`
- 渲染：原 `<SectionHeader label="速读" count={skim.length} />` 替换为三个
  小 sub-header（仅当对应桶非空时显示）：
  - `今日新增 ({skimToday.length})`
  - `本周累积 ({skimWeek.length})`
  - `更早未决 ({skimOlder.length})` —— 默认折叠（点击展开），避免无限刷
- 排序仍按 `created_at desc`，保留 SkimCard 形态不变

### C. NavBar 未决 badge

**frontend/src/components/Sidebar.tsx**（或 NavBar / AppShell 实际位置）：
- 新增 `useUndecidedCount()` hook：`useQuery(["papers", "undecided-count"], () => listPapers({ status: "new" }).then(r => r.length), { staleTime: 60_000 })`
- Papers 链接旁挂 `<Badge>{count}</Badge>`（>0 时显示），count >= 100 显示 "99+"
- 跑完 run-sub job 后 invalidate（在 useJobPolling 里加 `qc.invalidateQueries(["papers", "undecided-count"])`）

- ❌ macOS 专属 dock badge / Win taskbar overlay icon
- ❌ 未决 paper 提醒重发（只在 run 完瞬间弹一次）

## 风险

- **Win 11 通知静默**：focus assist / Do Not Disturb 时通知不弹（系统级，不可控）。验收时确认 focus assist 关。
- **浏览器 Notification 权限**：首次 dev 测试需用户允许；记录授权状态在 localStorage 防重复请求
- **created_at 时区**：后端 SQLite 存 UTC，前端按 local 比"今天 0:00"。`new Date()` 默认 local，OK
- **未决 badge 误差**：list 接口要支持 `?status=new`（已有，见 PaperListPage 实测调用）
