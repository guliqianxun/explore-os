# ft-020 解读器 L1+L2

## 目标

让解读器从「生成一段中文 TL;DR」升级为**结构化的逻辑还原 + 论文内反向信号复盘**。
所有产出都强制 cite 到 ft-019 的 `material_id`，无 cite 的 claim 直接丢弃——这是抑制幻觉的硬约束。

## L1：claim 抽取 + evidence 映射

**输入**：一篇 paper 的全部 `extract_*` material（来自 ft-019）。
**输出**：`interpret_claims` 表 + `interpret_claim_evidence` 关联表。

### claim 定义
论文中作者明确做出的可验证陈述。形态如：
- "We propose X, which achieves Y on benchmark Z"
- "Our method reduces FLOPs by N% compared to baseline"
- "Ablation on component C shows it contributes M points"

每个 claim 必须 cite 至少一条 evidence：figure / table / equation / 具体 section 段落。

### 表结构
```
interpret_claims:
  claim_id (pk)
  paper_arxiv_id
  text          (claim 本体，中文化后的简短陈述)
  text_en       (原文 span，可空)
  claim_type    (proposal / result / ablation / theoretical)
  source_section_path
  confidence    (LLM 自评 0-1)

interpret_claim_evidence:
  claim_id (fk)
  material_id   (引用 extract_*.material_id)
  relation      (illustrates / quantifies / supports)
```

## L2：论文内反向信号复盘

**严格边界**：只读论文内已有的反向证据，**禁止引用论文外 prior work**（待 L1+L2 跑稳后重审，预留集成口）。

### 反向信号来源
1. limitation 章节明确写出的限制
2. ablation 表中性能下降的 component
3. failure case / discussion 中的负面结果
4. cited prior work 在 related work 段落里被作者承认更优的指标

### 表结构
```
interpret_counter_signals:
  signal_id (pk)
  claim_id (fk, 必须挂在某个 claim 上)
  text          (反向信号陈述)
  signal_type   (limitation / ablation_drop / failure_case / prior_work_better)
  evidence_material_id   (必填，挂到具体 material)
```

## 接口契约

```python
# interpret/interpreter.py
class Interpreter(Protocol):
    def interpret(self, paper_arxiv_id: str) -> InterpretResult: ...

@dataclass
class InterpretResult:
    claims: list[Claim]
    counter_signals: list[CounterSignal]
    # 兼容旧版：保留 tldr / deep / narrative 不在本 ft 范围，由现有模块继续产出
```

## 现有模块的去留

| 现有 | 处理 |
|---|---|
| `interpret/tldr.py` | 保留，独立路径，不依赖 L1/L2（短期内邮件渲染兜底用） |
| `interpret/deep_interpret.py` | 重构：以 L1 claims + L2 signals 为输入，生成 4 段（method_summary / key_innovation / limitations / for_you） |
| `interpret/narrative.py` | 保留，不变 |
| `interpret/figure_picker.py` | 重构：从 L1 claims 反查最关键 evidence figure 作为封面 |
| `interpret/figure_classifier.py` | 保留，标签作为 figure material 的 metadata 增强 |

## CLI

```
python manage.py interpret_paper <arxiv_id>     # 跑 L1+L2
python manage.py inspect_claims <arxiv_id>       # 打印 claim 树 + evidence cite + counter_signals
```

## 验收标准

1. 一篇典型 ML 论文跑完，产出 5-15 个 claim，每个 claim 都有 ≥1 evidence_material_id
2. 同一篇至少能扫到 1 条 counter_signal（限制段或 ablation drop）
3. **强制 cite**：解读器拒绝输出无 cite 的 claim（LLM 返回未 cite 项时直接丢弃，记日志）
4. L2 signal 必挂在某个 claim_id 上（schema 强制）
5. 重构后 `run_subscription` 走 L1+L2 → deep_interpret 链路仍能产出邮件

## 风险

- LLM 自由抽 claim 偏离原文：用 prompt 约束 + 后处理 fuzzy match 到 section raw_text 再保留
- counter_signal 漏召：limitation 段落可能没有，要兜底扫 ablation 表数值差
- 成本上涨：claim 抽取按 section 流式分批，命中缓存（`paper_arxiv_id + section_path` 哈希）

## 工作量估计

- 1 天：models + migrations + Interpreter 接口骨架
- 1.5 天：L1 claim 抽取 prompt + 后处理 + cite 校验
- 1 天：L2 反向信号扫描（limitation + ablation 双路径）
- 0.5 天：deep_interpret 接入新结构 + 邮件兼容
- **合计 ~4 天**

## 非目标

- ❌ 跨篇 claim 关联（→ v1.x 跨篇图谱）
- ❌ 引用论文外 prior work 做批判（暂禁，集成口预留）
- ❌ claim 之间的支持/矛盾关系图（→ ft-021 渲染层做）
