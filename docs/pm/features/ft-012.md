# ft-012 图表提取 + LLM 分类 + 多模态解读

## 目标
从精读篇的 PDF 中提取所有图像，用多模态模型（qwen3.6-plus）给每张图分类，
挑选**框架图**渲染进邮件，并用图 + 方法文本做综合解读。

## 图像提取
- 工具：`pymupdf`（fitz）`page.get_images()`
- 对每个 page 抽出嵌入图像，落盘
  `media/figures/<arxiv_id>/p<page>_i<index>.png`
- 同时存该图位置附近的 caption 文本（图像上下约 200 字符）
  → `media/figures/<arxiv_id>/p<page>_i<index>.caption.txt`
- 去噪：丢弃 W/H < 100px、或宽高比极端（logo / line / header）的小图

## 分类
对每张图调多模态 LLM（qwen3.6-plus），prompt：
```
给出以下图像的分类，只输出一个标签（单选）：
  architecture  — 模型/方法架构图（含 pipeline / framework / overview）
  result_figure — 实验结果曲线 / bar / loss 曲线
  result_table  — 表格形式的实验结果
  qualitative   — 定性结果（生成样本 / 可视化对比）
  dataset       — 数据集样例 / 统计
  ablation      — 消融分析图表
  misc          — 其他
```
- 走百炼多模态 OpenAI 兼容：`{"role":"user","content":[{"type":"image_url",...},{"type":"text",...}]}`
- 结果落盘：`media/figures/<arxiv_id>/index.json`
  ```json
  {
    "figures": [
      {"path": "p01_i00.png", "caption": "...", "kind": "architecture", "conf": 0.9},
      ...
    ]
  }
  ```
- 建立索引：`media/figures/_index.sqlite`（简单 kv：arxiv_id → figures 列表）
  便于后续按类型检索（"给我本周所有 architecture 图"）

## 多模态解读
精读档的 deep_interpret 升级：
- 先挑一张 `kind=architecture` 的图（若有），否则挑第一张大图
- 调 qwen3.6-plus：图 + method 章节文本 → 产出：
  ```
  method_summary:   方法怎么做的（150 字）
  key_innovation:   和现有工作相比的关键创新点（2-3 条 bullet）
  limitations:      局限 / 未解决问题（1-2 条）
  for_you:          基于 perspective 的个人化解读
  ```
- 失败降级：只用文本的 deep_interpret（不带图）

## 邮件呈现
- 精读块中 "框架图" 子区：渲染 `<img src="cid:..." />` 内嵌
- Email 附件用 `django.core.mail.EmailMessage.attach` + CID 引用

## 文件范围
- `interpret/figure_extractor.py`
- `interpret/figure_classifier.py`
- `interpret/deep_interpret.py`（升级版）
- `delivery/email_renderer.py`：支持内嵌图
- `delivery/email_sender.py`：附件 CID 注入

## 测试
- mock 多模态 LLM 响应（返回固定分类）验证分类落盘
- figure 提取用 fixture PDF（小样本）
- 集成测试跳过真实多模态调用（可选开关 `--live-multimodal`）

## 验收
- 精读 paper 能提取 ≥3 张图
- 至少 1 张被分类为 architecture（人工验）
- 邮件里该图内嵌可见
- qwen3.6-plus 单次调用成本 ≤ 1 元

## 风险
- 多模态单次调用成本可能超预算：按订阅 `LLM_DAILY_BUDGET_CNY` 守门
- PDF 内嵌图可能是矢量 PDF 片段，pymupdf 直接抽像素形式不一定清晰：降级方案是渲染对应 page 的裁剪区域
