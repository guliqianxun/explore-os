# ft-039 Primary 卡重塑 + pdfplumber fast figures

## 触发

ft-031 brief 三段分桶落地后，「主要论文」区只是放大版的 SkimCard，没有发挥
brief / claim 数据的价值。用户引导：
1. 论文卡下半区放方法概要（markdown）+ 创新点 + 局限
2. 挂 Top 3 claims 预览（懒加载）
3. 图源用 markitdown / pdfplumber 抢速度（docling ~30s 太慢）

## 决策

1. **三层呈现**：主体内容（abstract / 标题 / 关键词）→ A+B（方法 + 创新 / 局限）
   → E（claims 折叠预览）
2. **图源 fast lane**：pdfplumber 抽 image-heavy 页整裁 PNG，与 docling 的
   `media/figures/` 解耦；落 `media/figures-fast/<arxiv_id>/`，最多 3 张
3. **触发**：detail GET 时 fire-and-forget（与 ensure_pdf_async 并列）
4. **List DTO 扩字段**：直接把 `method_summary_zh` / `limitations` 塞 list 响应；
   ~700 字符/篇，N 篇 list 几 KB 增量可接受
5. **Claims preview 默认折叠**，点开懒加载 detail；显示 Top 3（claim_type / page）
6. **MetaCards（3 标签卡）从 Primary 卡下沉**：Materials / Claims / AI Summary
   原本要点击展开，现在 A+B 直出，3 标签淘汰

## 范围

### A. fast figures
- `apps/extract/figure_pdfplumber.py`（新）
  - `extract_figures_fast(pdf_path, arxiv_id) -> list[Path]`
  - 启发式：page.images 非空 + 并集 bbox 占页面 ≥10% → page.crop().to_image(150 DPI)
  - 上限 3 张，已抽则跳过
- `apps/papers/pdf_auto.py::ensure_figures_fast_async` — `_FAST_INFLIGHT` 守门，
  detail GET 时与 ensure_pdf_async 并行触发
- API: `GET /api/papers/<id>/figure-fast/<seq>.png` (`FigureFastView`)

### B. Primary 卡 A+B
- `BriefSummary.tsx`（新）— react-markdown 渲染 method_summary，左红右蓝双列
  展示 key_innovation / limitations
- 数据来自 list DTO 扩字段（method_summary_zh / limitations）

### C. Primary 卡 E
- `ClaimsPreview.tsx`（新）— `useState(false)` 默认折叠；展开 → useQuery
  `enabled` 触发 detail 拉取；显示 Top 3 claims（claim_type / page）

### D. PaperCard / HeroPaperCard 接入
- 砍掉 MetaCards 引用
- 图源：`apiBase/papers/<id>/figure-fast/1.png`（错误时 onError 隐藏整图区）
- 挂 BriefSummary + ClaimsPreview
