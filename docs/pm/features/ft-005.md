# ft-005 推送去重 & 运行历史

## 目标
保证同一条目不会在同一订阅内重复推送；保留每次运行的审计轨迹与成本。

## 设计

### 去重键
跨 source 的统一标识优先级：
1. `arxiv_id`（arXiv 或 HF Papers 引用的原 paper）
2. `doi`
3. `source_key + external_id`（兜底）
4. `title_norm`（辅助，模糊匹配防漏网）

### 表
- `DeliveredItem`：`subscription_id / dedup_key / first_delivered_at / last_seen_at`
  - 下次运行检索到同键→跳过。
- `SubscriptionRun`：`subscription_id / trigger(cron|manual) / started_at / finished_at / status / items_found / items_new / items_delivered / llm_cost_cny / notes`
- `ItemCache`：`dedup_key / source_key / payload(JSON)`（原始 item 缓存，供重试 / 调试 / 解读引用）

### 策略
- 去重窗口默认永久（同订阅一次即可），可按订阅配置 TTL（如"30天后可再推"）—— MVP 先不做 TTL。
- 跨订阅不去重（两个订阅关心同一论文互不影响）。

## 验收
- 连续两天同关键词运行，第二天不再推送已送达的 paper。
- arXiv 拿到的 paper 与 HF Papers 拿到的同一篇能被识别为同条，只推一次。
- `SubscriptionRun` 可通过 Django admin / Navicat 查阅，成本列可读。
