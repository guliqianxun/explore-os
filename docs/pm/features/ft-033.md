# ft-033 Brief 内容处理层（PaperBrief）

## 战略上下文

ft-029 Reading Station 上线后用户实测发现：**Today's brief 视图卡片没内容**——只有 title + arxiv_id + 元数据，没有任何叙述文字（abstract / TL;DR / 翻译）。

根因（4/29 调查）：
- `apps/papers/Paper` schema 只存元数据，**没有 abstract / tldr / abstract_zh 字段**
- 老邮件渲染（ft-006 / ft-009 / ft-014）的内容处理 pipeline 在 `interpret/interpretation.py`：
  - `skim_interpret(item) → SkimOut(abstract_zh, keywords)` — 中文翻译 + 3-5 关键词
  - `deep_interpret(item) → DeepOut(method_summary, key_innovation, limitations, for_you, ...)` — 视角注入精读
  - `perspective_prefix(spec)` — 从 subscription yaml 读 PerspectiveSpec 注入 system prompt
- 但**新 ingest 链 (apps/extract + apps/interpret_v2) 完全没接这个 pipeline**——dataclass 不落 DB，以前是抓→解读→发邮件→丢

本 ft 是把老邮件内容处理 **bring back 到 Paper-centric 数据层**，让 brief / detail / 任何 UI 视图都能吃到同一份缓存。

## 决策（PM 拍板 4/29）

| # | 决策 | 备注 |
|---|---|---|
| 1 | **复用 `interpret/interpretation.py` 现有函数**（`skim_interpret` / `deep_interpret` / `perspective_prefix`）| 不重写；只在 apps 层加缓存壳 |
| 2 | 新表 `PaperBrief` (OneToOne with Paper) | 落 SQLite；同库前缀 `papers_brief` |
| 3 | **`Paper.abstract` 加字段** | 从 docling 第一个 abstract section 回填；ingest 时也填 |
| 4 | **触发：手动 + opt-in 自动**——默认不自动跑避 LLM 失控 | 手动 endpoint + `--auto-brief` ingest flag |
| 5 | **perspective 从 active subscription yaml 读**；fallback `researcher` preset | 多订阅时取第一个 active |
| 6 | DTO：list 暴露 `tldr_zh + keywords` 短字段；detail 暴露完整 PaperBrief | list 不重，避 N+1 |
| 7 | brief 缺失（用户没 generate）→ 前端 fallback 显示英文 abstract（截 200 字）| KISS 兜底 |
| 8 | 跨 paper 重新 generate：覆盖式更新（`updated_at` 跟随）| 不保留历史版本 |
| 9 | 视觉：主要论文卡 = abstract_zh + keywords chips；速读卡 = tldr_zh 一句 | 邮件级密度 |

#### 3. 内容生成器（壳）

```python
# apps/papers/brief_generator.py（新文件）
from sources.base import Item
from interpret.interpretation import skim_interpret, deep_interpret
from subscriptions.loader import PerspectiveSpec, load_subscriptions

def _build_item(paper: Paper) -> Item:
    """从 Paper + extract 数据组装 ad-hoc Item 喂给老 pipeline。"""
    return Item(
        external_id=paper.arxiv_id or paper.key,
        title=paper.title,
        abstract=paper.abstract,
        url=...,
        source_key="reuse",
        group="papers",
    )

def _resolve_perspective() -> PerspectiveSpec:
    """从 active subscription 读；多订阅取第一个；无配置 fallback researcher。"""
    try:
        subs = load_subscriptions()
        for s in subs:
            if s.active and s.perspective:
                return s.perspective
    except Exception:
        pass
    return PerspectiveSpec(preset="researcher")

def generate_brief(paper: Paper, *, regenerate: bool = False) -> PaperBrief:
    """复用老 pipeline 生成 brief 并落库。"""
    if not regenerate and hasattr(paper, "brief") and paper.brief.abstract_zh:
        return paper.brief
    item = _build_item(paper)
    persp = _resolve_perspective()
    skim = skim_interpret(item, persp)
    deep = deep_interpret(item, persp)  # iter-002 占位返回也无妨
    brief, _ = PaperBrief.objects.update_or_create(
        paper=paper,
        defaults=dict(
            abstract_zh=(skim.abstract_zh if skim else ""),
            keywords=(skim.keywords if skim else []),
            method_summary_zh=deep.method_summary,
            key_innovation=deep.key_innovation,
            limitations=deep.limitations,
            for_you=deep.for_you,
            tldr_zh=_compose_tldr(skim.abstract_zh if skim else paper.abstract),
            perspective_used=persp.custom or persp.preset,
            model_used=...,  # 从 LLMResult 取
        ),
    )
    return brief

def _compose_tldr(text: str, max_len: int = 80) -> str:
    """从 abstract_zh 头部截一句话作 TL;DR；保完整句末。"""
    if not text:
        return ""
    head = text[:max_len]
    for sep in ("。", "；", ". ", ";"):
        idx = head.rfind(sep)
        if idx > 30:
            return head[:idx + 1]
    return head + "…"
```

## 风险

1. **LLM 调用失控**：默认手动触发 + ingest 不自动跑可控；但用户批量点 regenerate 可能消耗大。考虑加每日预算上限（`interpret/cost.py` 已有 ft-008 budget 机制可复用）。本 ft 暂不强制，先看用户使用习惯。
2. **abstract 回填来源不稳**：docling 第一 section 不一定标准 "abstract"——有论文会把 introduction 当第一节。fallback：找 path icontains 'abstract'，找不到再取 ordinal=1。极端情况留空 → 前端 fallback `paper.title` 显示。
3. **perspective 多订阅冲突**：取第一个 active 是简化方案；用户若多订阅风格差异大，brief 全局风格可能不符。v1.3+ 引入 per-paper perspective override。
4. **deep_interpret 当前是 iter-002 占位**（看 `interpret/interpretation.py:127`）：返回空 method_summary 等。本 ft **不升级 deep_interpret 的实质能力**（那是 ft-014 的延续工作，超出范围）；先把数据通路打通，DeepOut 字段空着也能跑（前端 fallback）。
5. **skim_interpret 只用 abstract**：如果 paper.abstract 因 docling 异常为空，skim 直接返回 None — brief 表 abstract_zh 留空。前端要 graceful：`tldr_zh || abstract.slice() || title`。
6. **OneToOne related_name='brief'** 与 Python 内置 `brief` 词冲突？Django 不报错；但代码可读性略差。可考虑 `related_name='paper_brief'`，DRF nested 字段名仍叫 `brief`。

### Spec 之外的增量决策（用户实测驱动）

1. **D10 fallback：paper.abstract 空 → 从 Section 实时拉**
   - 根因：0006 backfill migration 仅 migrate 时跑一次，新 ingest 的 paper 不会触发；ingest 链不写 paper.abstract
   - 修：`_build_item` 加 `_abstract_from_sections` fallback（path icontains 'abstract' 优先 / fallback ordinal 1）；找到回写 paper.abstract 缓存

2. **D11 接通 `deep_interpret_rich` 替代 `deep_interpret`**
   - 根因：spec 调的是 `deep_interpret`（iter-002 占位返回空 method_summary / for_you 等）
   - 修：改调 `deep_interpret_rich`（接收 PaperChunks + Caption[]）；新增 `_build_chunks` / `_build_captions` / `_classify_bucket_from_path` helper 把 docling Section 表归桶
   - 实测产出（GHQNYSJY）：abstract_zh 918 字 + method_summary 744 字 + key_innovation 2 项 + limitations 2 项 + for_you 258 字

3. **D12 list DTO 加 `abstract_zh` 短字段**
   - 根因：用户实测发现 list 卡片只显示 tldr_zh（一句精炼）信息密度不够
   - 修：list DTO 新增 `abstract_zh`；BriefView lead 优先级改 `abstract_zh > tldr_zh > abstract_en` 截 320 字

4. **D13 list 卡片自动撑高 + 英文原文展开按钮 + 图文比例 fr 自适应**
   - 用户反馈"自动空间 / 塞下摘要 / 展开英文 / 图文比例适当"四点
   - 修：HeroPaperCard 去 `line-clamp-6` → `whitespace-pre-line` 自然撑；加 `abstractEn` prop + `▸ Show original abstract` 折叠按钮（与 BriefSection 同款）；grid 从固定 px 改 `2fr_1fr`（Hero）/ `3fr_1fr`（PaperCard）让图随容器自适应
   - PaperCard 同款改造

5. **D14 BriefSection 在 brief 未生成时直接显示英文 abstract**
   - 根因：之前空白虚线框只有"Generate brief"按钮，用户不点就完全无内容
   - 修：no-brief 状态把英文 abstract 内联展示，[Generate brief] 按钮挪到右上小钮
