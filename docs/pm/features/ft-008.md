# ft-008 综合分打分 + rerank + 自适应 Top-N

## 目标
把"按时间取前 N"的简单截断，换成"按综合分排序 + 自适应 Top-N 分档"。
为 ft-009 的精读/略读分档提供稳定的分数输入。

## 综合分定义

```
score = 0.3 × relevance + 0.7 × hotness
```

用户选择偏热度主导（0.7）：高热论文带拉力，更利于扩展研究思路；相关性只用于基线兜底。

### relevance（0–1）
- 用阿里百炼 `text-embedding-v3`（或 v1，看可用性）
- 先对订阅 `interests` 做一次 embedding 并缓存（订阅配置不变则不重算）
- 每条 Item：`title + abstract` 做 embedding → 与 interests embedding 余弦相似度
- 批量调用（一次可发 ≤25 条）降成本

### hotness（0–1）
MVP 现成信号：
- **HF Papers upvotes**（daily_papers 条目里有 `upvotes` 字段）：`min(upvotes / 100, 1.0)`
- **arXiv 无热度信号**：给默认值 0.1（保底不为 0，让相关性能起作用）
- **跨源命中加成**：若某 paper 在 arxiv + hf_papers 都命中，hotness += 0.1（capped 1.0）

后续（ft-013 引入）：
- GitHub stars（如果 paper 关联仓库）
- Twitter 提及数
- HF Papers 累计讨论数

### 失败降级
- embedding 调用失败 → relevance=0.5（中性）
- HF upvotes 缺字段 → hotness=0.1

## 自适应 Top-N

```python
top_items = [it for it in scored if it.score >= 0.75]
if len(top_items) == 0:
    top_items = [scored[0]]              # 保底 1 篇
top_items = top_items[:3]                # 上限 3 篇
```

略读档 = 其余全部按分排序截到 `delivery.max_items`。

## 数据结构改动

在 `sources.base.Item` 的 `raw` 字段内（不改 dataclass 签名）由 pipeline 阶段写入：
- `raw["score"] = {"relevance": 0.81, "hotness": 0.42, "total": 0.54}`
- `raw["tier"] = "deep" | "skim"`（由 ft-009 消费）

保持 Item dataclass 稳定，避免侵入 fetcher 接口。
