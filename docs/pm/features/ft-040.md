# ft-040 Brief 双语 + ingest 链路完善

## 触发

ft-038 i18n 落地后用户提出：summary 一直是中文，英文 paper 也强制翻成中文
没必要。期望「LLM summary 用原语言总结，输出时按需求转化」。

同时发现 ingest 链路完整性问题：
- 上传 PDF / arxiv id / URL 后，`Paper.abstract` 没被填（订阅链路有，ingest
  漏了）
- `key_innovation / limitations` 等 brief 字段全空 — 因为 ingest 链路只跑
  extract → interpret → render，**不**触发 brief 生成

## 决策

### 双语 summary
1. **LLM 端按 paper 语言生成**：CJK 启发式检测，英文 paper → 英文 prompt 输出
   英文 summary，中文 paper → 中文 prompt
2. **schema 不大改**：`PaperBrief` 加 `lang` 字段；`abstract_zh / method_summary_zh`
   等字段名保留向后兼容，**内容反映 paper 语言**（命名将就）
3. **Perspective 注入也双语**：英文 paper 用 `[Perspective]` + `PRESETS_EN`，
   中文 paper 用 `【视角】` + `PRESETS`。否则 LLM 看到中文标签会拐回中文输出
4. **前端 lang badge**：UI 语言 ≠ brief.lang 时在「方法概要」标题旁显示
   `EN` / `中` 小角标
5. **不做即时翻译**：runtime translation 留给后续 ft（ft-041 候选）

### ingest 链路完善
1. **extract 后回填 `Paper.abstract`**：取第一段 Section.raw_text 头部 ~2000 字
2. **chain 完成后 fire-and-forget brief**：独立 job `ingest-brief:<arxiv_id>`，
   不阻塞 chain 三阶段；LLM 失败仅 log，不影响主流程
3. **存量数据补救**：mgmt 命令 `backfill_briefs` 一次性给所有 extract 跑过但
   brief 空的 paper 补 brief

## 范围

### A. 双语 LLM
- `apps/llm/lang_detect.py`（新）：CJK 字符启发式
- `apps/llm/prompts/skim_en.py` / `deep_en.py`（新）：英文版 prompts，与中文
  版同 JSON schema
- `apps/llm/services/skim_interpret.py`：
  - `PRESETS_EN` 字典 + `perspective_prefix(p, lang='zh')` 双语
  - 调用时 `detect_paper_lang` → 选 prompt → `SkimOut.lang`
- `apps/llm/services/deep_interpret.py`：同上 + user 消息 section header 双语
- `apps/llm/services/brief_generate.py`：`BriefData.lang` 透传
- `apps/llm/services/subscription_persist.py`：写 `PaperBrief.lang`
- `apps/papers/brief_generator.py`：写 `PaperBrief.lang`
- Migration `apps/papers/migrations/0008_paperbrief_lang.py`：加 `lang` 字段
- `apps/api/serializers/papers.py` + `views/papers.py`：list DTO 暴露 `brief_lang`，
  detail `_serialize_brief` 也加 `lang`
- 前端 `BriefSummary.tsx`：`briefLang` prop + UI ≠ brief.lang 显示 EN/中 badge

### B. ingest 链路完善
- `apps/api/ingest.py`：
  - `_run_extract` → 调 `_backfill_abstract_from_sections` 写 `Paper.abstract`
  - chain 末尾 `jobs.enqueue(_run_brief, arxiv_id, name=f"ingest-brief:{arxiv_id}")`
  - `_run_brief` LLM 调用，失败 swallow（log only）
- `apps/papers/management/commands/backfill_briefs.py`（新）：`--apply` /
  `--limit N` / `--paper <id>` 三参数

### C. 杂项修复
- `useJobPolling.ts`：getJob 拿到 404 → 把本地 job 标 terminal `done`
  （sidecar 重启会丢 in-memory `_JOBS`，老 job_id 永远 404 → UI 卡住）

## 验收

| 项 | 标准 |
|---|---|
| 英文 paper 跑 brief | `brief.lang == 'en'`，summary 内容是英文 |
| 中文 paper 跑 brief | `brief.lang == 'zh'`，summary 内容是中文 |
| UI 语言 = brief 语言 | 不显示 lang badge |
| UI 语言 ≠ brief 语言 | 「方法概要」标题旁显示 EN/中 badge |
| 上传 PDF | extract 后 `Paper.abstract` 非空（取 Section 头部）|
| ingest 链路完成 | chain 三阶段成功后，`ingest-brief:<id>` job 异步跑出 brief |
| 老 paper 缺 brief | `backfill_briefs --apply` 一次补齐 |
| pytest | 391 passed |

## 不在范围

- ❌ Runtime translation（UI 是中文但 brief 是英文 → 实时翻译）— 留 ft-041
- ❌ 字段重命名（`abstract_zh` → 中性 `abstract`）— 兼容老消费方留着
- ❌ jobs 持久化（in-memory `_JOBS` 重启丢）— 留 ft 单独立项
- ❌ legacy email pipeline（`interpret/interpretation.py`）双语 — 暂未修，
  老路径仍中文

## 风险

- 字段名 `_zh` 但内容可能是英文 — 命名 vs 内容不对应。短期可接受，
  长期重命名工程量大
- LLM 失败导致 brief 空：UI 已有占位（"Abstract not available"）兜底

## 工作量

实际 ~1 天（双语链路 + ingest 修复 + 调试）。
