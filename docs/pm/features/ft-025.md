# ft-025 自动更新 + CUDA/CPU 双轨

## 目标

1. **自动更新**：electron-updater 接入，开机自动检查新版本
2. **CUDA / CPU 双轨**：两份 PyInstaller spec，自用走 CUDA，CPU 接口留给未来分发
3. **不签名**：自用阶段跳 Apple Dev / Windows EV cert（公开分发延后到 v1.x）

## CUDA / CPU 双轨设计

### 方案

```
pyproject.toml  →  [tool.uv.sources]
                   torch = { index = "pytorch-cu124", marker = "extra == 'cuda'" }
                   torch = { index = "pypi", marker = "extra == 'cpu'" }
```

通过 PyInstaller spec + uv extras 区分两个产物：

```bash
# CUDA bundle（自用）
uv sync --extra cuda
uv run pyinstaller build/sidecar-cuda.spec

# CPU bundle（分发接口，本 ft 只跑通流程，不实际分发）
uv sync --extra cpu
uv run pyinstaller build/sidecar-cpu.spec
```

### electron-builder 多 target

```yaml
# build/electron-builder.yml
extraResources:
  # CUDA build artifact（自用）
  - from: dist/sidecar-cuda
    to: sidecar
# 命令行选 cpu / cuda：
# electron-builder --config build/electron-builder.yml --config.extraResources.0.from=dist/sidecar-{flavor}
```

### 标识

应用启动时检测 sidecar bundle 类型（读 `sidecar/.flavor` 文件 = "cuda" / "cpu"），UI 状态栏显示「⚡ CUDA」/「🐢 CPU」。

## 自动更新

`electron-updater` 默认：
- macOS / Windows：从 GitHub Releases 自动检查
- 启动时 `autoUpdater.checkForUpdatesAndNotify()`
- 有新版时弹 toast「下载并重启」按钮
- 自用阶段 release 走 GitHub private repo（用户手动下载也可）

```typescript
// electron/src/updater.ts
import { autoUpdater } from "electron-updater";
import { dialog } from "electron";

autoUpdater.on("update-downloaded", () => {
  dialog.showMessageBox({
    type: "info",
    message: "新版已下载，重启即可应用",
    buttons: ["重启", "稍后"],
  }).then(({ response }) => {
    if (response === 0) autoUpdater.quitAndInstall();
  });
});

export function startAutoUpdate() {
  autoUpdater.checkForUpdatesAndNotify();
}
```

`build/electron-builder.yml` 加：
```yaml
publish:
  provider: github
  owner: <user>
  repo: explore-os
  releaseType: release
  private: true   # 自用，私 repo
```

| Linux | 无影响 | — |

文档里加一段「首次运行说明」教用户绕过。

## 验收

1. `npm run build:cuda` 产出 CUDA NSIS / DMG，体积 < 2GB
2. `npm run build:cpu` 产出 CPU 版本，体积 < 1GB
3. CUDA bundle 在 4090 实机跑通 leworldmodel 抽取（GPU 利用率验证 > 0%）
4. CPU bundle 在无 GPU 机器跑通同样 paper（速度可接受 ~3-5 min/paper）
5. UI 状态栏显示 sidecar flavor 标识
6. 模拟版本号 bump，手动构建并发布 GitHub Release，旧版客户端 24h 内自动检测到并提示更新
7. **不破现有功能**：CUDA 版的体验与 ft-024 完成时无差异

## 范围

**新增**：
- `build/sidecar-cpu.spec` — CPU 版 PyInstaller spec
- `build/electron-builder-cpu.yml` — CPU 分发配置（可选，与 cuda 共用主配置）
- `electron/src/updater.ts`
- `electron/src/flavor.ts` — 检测 sidecar 类型
- `frontend/src/components/FlavorBadge.tsx` — 状态栏标识

**修改**：
- `pyproject.toml` — `[project.optional-dependencies]` 添加 `cuda` / `cpu` 两个 extras + `[tool.uv.sources]` 条件 index
- `electron/src/main.ts` — 启动时调 `startAutoUpdate()`
- `electron/package.json` — 加 `electron-updater` 依赖 + build:cuda / build:cpu 脚本

**严禁触碰**：
- 任何业务代码（apps/extract / apps/interpret / apps/render / apps/api / apps/core）
- 前端业务组件（除新加 FlavorBadge）

## 工作量

- 1 天：pyproject.toml 双轨 + 两份 PyInstaller spec
- 0.5 天：electron-builder build:cuda / build:cpu 脚本
- 1 天：electron-updater 接入 + 私 repo release 配置 + flavor 标识
- 0.5 天：CPU bundle 实机测试（找一台无 GPU 机器）
- 1 天：buffer
- **合计 ~4 天**

## 风险

- **CPU 版 PyInstaller**：部分 docling 内部 op 可能 fallback 时 import 失败；hidden imports 调一遍
- **GitHub Releases 私 repo + autoUpdater**：需要 token 注入到 build env；autoUpdater 私 repo 模式有 OAuth 流程，文档不全，可能要踩坑
- **macOS 自动更新**：未签名应用 autoUpdater 会拒绝（强制要求签名）→ macOS 自用阶段降级为「手动检查 + 手动下载」

## 非目标

- ❌ 公开分发签名（→ v1.x，单独 ft）
- ❌ 增量更新（delta packages，电报式）—— 全量足够
- ❌ 多版本回滚 UI
- ❌ 国际化分发（CN / global 不同 channel）
