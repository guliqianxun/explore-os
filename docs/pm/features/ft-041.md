# ft-041 记忆/编排双层 — 观点状态机 + 事件日志 (H0)

## 战略上下文

explore-os 已建成完整信息管道（extract → interpret → brief → feed），但存在关键断层：
系统有 per-paper 的短时记忆（8 篇滑动窗口 → `for_you`），没有**跨 session 的累积用户模型**。

本 ft 不替代现有管道——在管道之上叠加**记忆层 + 编排层**。核心原子是**观点 (viewpoint / claim)**，不是论文。

**五态观点状态机**：

```
unseen → exposed → confirmed → linked → internalized
```

- **unseen**: 论文读了但这个观点没被注意（默认始态）
- **exposed**: 用户知道这个观点存在（读了 paper 自动进入）
- **confirmed**: 用户看了证据（展开 claim card / 放大 figure）
- **linked**: 用户把这个观点和另一个连起来了
- **internalized**: 用户在此基础上形成了自己的思考（写入了 thread）

两个正交的连续量：
- $A$（活跃度）: "这个 topic 在我脑子里还热不热" — 14 天半衰期
- $C$（固化度）: "这个 topic 有多少观点我真正消化了" — confirmed+ 观点占比

完整正式规范见 `docs/design/explore-os-formal-spec.md`。双层架构图见 `docs/design/explore-os-architecture.md`。

## 决策

| # | 决策 | 备注 |
|---|------|------|
| 1 | 原子是 $\mathcal{V}$（观点），不是 $\mathcal{P}$（论文） | 观点粒度天然跨 paper 可比 |
| 2 | $\sigma_v$ 五态向前不可逆（仅 linked → confirmed 在 unlink 时可退） | 用户不会"忘掉"验证过的观点 |
| 3 | 活跃度 $A$ 和固化度 $C$ 是连续标量，不是状态机 | 交叉位置描述学习阶段，无需额外状态 |
| 4 | $A$, $C$, $G$（缺口）不落库只计算 | 存最小事实，派生值现场算 |
| 5 | Crunch 周期每天 03:00（APScheduler），只重算 dirty topics | 事件来时只写状态行，不触发全局重算 |
| 6 | 事件来源：papers_user_* signals 自动 emit + 前端 API 上报 | 阅读状态变更覆盖 unseen→exposed；VIEW_EVIDENCE 等需前端上报 |
| 7 | `explore_vp_state` + `explore_vp_event` 表 | 状态行 + 追加日志 |
| 8 | Topic 种子从 paper.keywords + brief.keywords 提取 | mgmt command `seed_topics` |
| 9 | H0 只做状态机 + 事件积累 + seed topics | $A$/$C$ 计算和 gap 检测在后续 sprint |
| 10 | 单用户模式（user_id=1），表结构保留 user FK | 多用户扩展时只加 Index |

## 范围

### Backend — `apps/explore/` 新 Django app

#### 数据模型

```
explore_vp_state              每 (user, viewpoint_id) 一行
  state: {unseen, exposed, confirmed, linked, internalized}
  exposed_at, last_event_at, link_count, internalized_in

explore_vp_event              追加日志
  viewpoint_id, from_state→to_state, trigger, payload, created_at

explore_topic                 topic 分类法
  topic_id (slug), name, aliases, description, source

explore_topic_edge            topic 关系 DAG
  src→dst, relation: {prereq, sub, app, rel}

explore_activity              每日快照 (A, C)
  snapshot_at, topic, activity, consolidation

explore_claim_link            观点级交联
  src→dst, relation: {agree, conflict, refine}

explore_thread                用户线程
  title, body, viewpoint_ids, paper_keys

explore_thread_note           线程内笔记序列
  body, created_at

explore_open_question         未决问题
  question, topic_id, last_hit_at
```

#### Signals

| Signal | 触发 | 转移 |
|--------|------|------|
| `UserPaperStatus.post_save` | status=reading/read_kept | $\forall v \in \Delta(p)$: unseen → exposed |
| `HermesClaimLink.post_save` | 新建链接 | confirmed → linked (双方) |
| `HermesClaimLink.post_delete` | 删除链接 | linked → confirmed (双方，仅当该 v 无其他 link) |

#### API Endpoints

```
GET  /api/state/profile/           用户摘要: topics + A/C + viewpoint stats
GET  /api/state/activity/?topic=X  活跃度时间序列
GET  /api/state/gaps/              当前缺口列表
GET  /api/state/viewpoint/<id>/    单个观点状态 + 事件历史
POST /api/state/events/            前端上报 VIEW_EVIDENCE / THREAD_WRITE
GET/POST     /api/state/links/     观点交联 CRUD
DELETE       /api/state/links/<id>/
GET/POST     /api/state/threads/   线程 CRUD
POST         /api/state/threads/<id>/notes/
GET/POST     /api/state/questions/  未决问题
DELETE       /api/state/questions/<id>/
```

#### Management Commands

```
python manage.py seed_topics      从 paper.keywords + brief.keywords 种 topic
python manage.py crunch           手动触发每日 crunch (A + C 重算)
```

### 不做的

- 不自动建 topic 层级关系（llm clustering）
- 不接外部引用 API（canonical gap 留空）
- 不做 Calibration 自适应（$\lambda_A$ 手动设）
- 不做 synthesis 排列算法
- 不做 "Chat with memory"（v1.4 后半程）
